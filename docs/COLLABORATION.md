# Collaboration Guide

LittleCures is a distributed, open project. This document explains how we work together, make decisions, and stay coordinated.

## Where work happens

- **GitHub repository:** source code, issues, pull requests, and project boards.
- **GitHub Discussions:** async questions, ideas, and community conversations.
- **Documentation:** `docs/` and the `README.md` are the source of truth.
- **Real-time chat:** to be set up once a core group forms. Options include Discord, Slack, or a Matrix room.

When we set up real-time chat, this document will be updated with the invite link.

## How we make decisions

- **Issues first.** New work, bugs, and ideas start as GitHub issues.
- **Lazy consensus.** If no one objects within a reasonable timeframe, a proposal is accepted.
- **Pull request reviews.** Code and documentation changes require at least one review from a maintainer.
- **Maintainer circle.** A small group of maintainers handles escalations, security, and project health. Membership is public and rotates.

## Contributor roles

- **Casual contributor:** opens an issue, fixes a typo, answers a question.
- **Active contributor:** works on issues, reviews PRs, participates in discussions.
- **Maintainer:** merges PRs, triages issues, shepherds major workstreams.
- **Clinical or scientific advisor:** reviews medical and scientific accuracy.
- **Patient advocate or community member:** keeps the work grounded in patient and family needs.

All roles are open to anyone who acts in good faith and respects the code of conduct.

## Communication norms

- Prefer public channels (issues, discussions) over private messages. This keeps the project transparent and searchable.
- Be kind, direct, and evidence-based. Disagreement is expected; personal attacks are not.
- Respect time zones and availability. The project is mostly asynchronous.
- If a conversation becomes complex or heated, move it to a video call and summarize the outcome in writing.

## Onboarding

1. Read `README.md`, `docs/MISSION.md`, and `docs/WHITEPAPER.md`.
2. Run the project locally with `pnpm install` and `pnpm dev`.
3. Look at the [roadmap](ROADMAP.md) and open issues.
4. Comment on an issue you want to work on, or open a new one.
5. Open a small, focused pull request.

## Meetings

We do not hold mandatory meetings. We may introduce optional standups or review calls as the project grows. All meeting notes will be posted publicly.

## Working groups

As the project grows, we may form focused working groups around the four pillars:

- Trial matching
- Target and IP registry
- Federated learning
- Access and advocacy

Each working group will have a public issue label, a lead maintainer, and a regular written update.

## Conflict resolution

1. Discuss in the relevant issue or PR.
2. If unresolved, request mediation from a maintainer.
3. If still unresolved, the maintainers make a decision in the best interest of the project and patients.

Serious violations of the code of conduct are handled according to `CODE_OF_CONDUCT.md`.
