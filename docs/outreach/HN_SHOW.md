Post body:

```
Hi HN,

I have been building LittleCures, an open-source project focused on accelerating cures for children with cancer — starting with the deadliest and most neglected diseases.

The problem in a nutshell: pediatric cancer drugs are treated as an afterthought by industry (small market), the data is siloed across hospitals (rare tumors, no single institution has enough cases), and access is deeply unequal (~80% survival in high-income countries vs <20% in many low-income countries for the same disease).

What we are building, in order:

1. Open trial matching for pediatric cancers — a public tool that returns matched trials in seconds instead of days, in plain language.
2. An open registry of molecular drivers, patent status, and active research for the most neglected childhood cancers.
3. Federated learning software so hospitals can jointly train on rare tumor data without moving patient records.
4. Open IP + advocacy so what we build stays affordable and available.

Everything is MIT-licensed. Roadmap, decisions, and metrics live on GitHub. There is no proprietary product to sell — this is infrastructure meant to be used by anyone.

Repo: https://github.com/AEVentures/littlecures
Site: https://littlecures.org
White paper: https://github.com/AEVentures/littlecures/blob/main/docs/WHITEPAPER.md

We have `good first issues` open right now for engineers who want to help this weekend. And if you have expertise in pediatric oncology, federated learning, or open healthcare data, please open a discussion — we'd love your input.

Happy to answer questions.
```
